# Churp invitations

**Invite your people** creates a QR code, a ten-character short code grouped as `ABCDE-FGHJK`, and the full invitation link. The QR opens the same full link; users sign in or create an account, then confirm joining. Short codes can be entered in **Invitations → Have a link or code?**; case, spaces and the dividing hyphen do not matter. Links remain supported, including links created before short codes were added. A QR image can be saved for printing or sharing. The URL uses the configured `APP_URL`, which should be the public app origin, such as `https://app.churptree.com`.

All three share methods expire together after seven days. Possession grants member access only, subject to the inviter still being an admin of that Tree or Nest. Nest links/codes require existing Tree membership. QR images are generated locally by the server with a clear quiet zone, without sending invitation URLs to an external QR service. Only token and normalized-code hashes are stored. Successful joins do not consume the failed-invitation rate limit, so members sharing a school/church network can join normally.

**Nest information → About this Nest → Invite Tree members** lets a Nest admin choose one or more existing Tree members. Tree admins and admins of the containing Branch inherit this permission. Private Nests remain invitation-only. Selecting someone creates an invitation, not a membership. Invitees receive a live pending count beside the bird-envelope **Invitations** action, on phones and computers. The inbox lists Nest name, Tree, inviter and expiry, with Accept and Decline. It includes invitations across all of the user's Trees.

Accepting joins the Nest and its parent Branch, then opens the chat. The encrypted join boundary is set at acceptance: earlier messages and files are not shared with the new member. Declining does not join. Already-joined members are omitted from the picker. Pending rows show Invitation pending, and an admin can send another invitation after decline or expiry. Every join path consumes outstanding pending invitations for that person/Nest.

Inbox invitations are recipient-bound. Removing someone from a Tree deletes their pending invitations there; rejoining the Tree does not resurrect them. Expiry, lost inviter permissions, and Nest/Tree deletion remove unusable invitations from the inbox and prevent acceptance. These are in-app invitations; the account-recovery email provider is not required.

Storage: `invitations` remains compatible with previous links, `invitation_codes` stores its hashed short-code lookup, and `nest_invitations` stores recipient-specific requests. Foreign keys cascade when a Nest or Tree is deleted. Tests decode the actual PNG with an independent QR decoder and cover permissions, recipient isolation, atomic bulk validation, revocation, expiry, persisted requests and join-history boundaries.
